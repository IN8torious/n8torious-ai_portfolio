## The kernel constitution — five invariants, each with a test

*From the review thread; adopted by Nathan 2026-10-31. D7 is the first article; these five are its enforcement shape. Every invariant names its level — IN-PAGE (proven in the single-file build) or PLATFORM (must be enforced and tested in the Prodigy runtime; the page holds it by construction only). A claim without a level is a diagram.*

1. **Identity cannot mint capability.** AccessContext carries who; grants live in the registry and workflow definitions. Test — PLATFORM: a valid identity with no grant for a tool is denied at policy evaluation. IN-PAGE: swapping the docked model changes no authority (battery-asserted).
2. **Capability cannot forge receipt.** Only the Archivist appends to the ledger. Test — PLATFORM: appends accepted from the archivist identity only. IN-PAGE: by construction (one ledger function, fed by run transitions only).
3. **Receipt cannot modify state.** The ledger is read-only toward the world — no write path from the EEL into any workspace. Test — PLATFORM: the append API exposes no state hooks; audit storage is separate. IN-PAGE: by construction.
4. **State cannot rewrite receipt.** History is hash-chained; tamper and verification breaks. Test — IN-PAGE, PROVEN in the hard-math suite: mutate a stored entry → `verifyChain()` returns false; restore it → true. PLATFORM: the same chain property over the persisted EEL.
5. **Systems cannot originate authority.** (D7 itself.) Approvals exist only as operator acts — one-use, hash-bound grants. Test — PLATFORM: no code path creates a grant without an operator identity (`approved_by` is never system-filled). IN-PAGE: the approval count moves only through the operator's tap.

*The hardening question, for this phase and every future one: which invariant must hold even when both shells are compromised? The answer: the execution-time capability check, and I4 — capability enforced at the tool boundary, over a history that cannot be quietly rewritten.*

## Kernel minimalism — the razor and the five services

*Adopted 2026-10-31 from an external review, on Nathan's explicit word — with one correction: hosts stay pluggable.*

**The razor.** For everything proposed for the kernel, ask one question: *does this belong in the kernel, or can it live in a host?* The kernel answers only two questions — **can this happen?** and **did it happen?** It does not plan, write, estimate, or know what Gemba means. Planning, language, memory physics, worlds, ontologies, tool packs, sensor packs, and agent personalities are host and shell concerns.

**The five services.** The kernel-facing architecture reduces to five services over the five primitives: **Identity Service · Capability Service · Proposal Service · State Service · Receipt Service**. The named agents map onto them — Vera is the Proposal Service's face, Sentinel the Capability Service's, Archivist the Receipt Service's — and every other agent (Corvus, Genki, Kami, and any future or custom agent) is a host-loaded plugin consuming capabilities, never a kernel component. The worlds belong to the Raijin shell; the kernel receives only signal, source, and confidence from them.

**The motto.** *The proposal moves. The constitution stays.* The proposal is the only thing that flows through the runtime — actor → router → capability check → state validation → receipt — while the core sits still and governs. Possession confers no power: whoever holds the proposal (router, sentinel, gate) cannot authorize it by holding it. Agents, models, sensors, shells, worlds, and whole reasoning systems are swappable precisely because none of them is the thing that moves or the thing that stays.

**The triad.** **SI Core = the Rules. The host (Muse, today) = the Intelligence. Raijin = the Experience.** The human is none of the three: the human is the authority all three answer to — the crew proposes, the operator disposes (D7).

**Hosts stay pluggable.** Muse is Nathan's host — the first host, not the substrate. The kernel exposes its five services and its constitution to any host (Muse, the Prodigy runtime, a future runtime) identically; no host is named inside the kernel. A direction that makes the core depend on one vendor's agent environment is rejected on the agnostic law, whoever proposes it. Shrink the coupling, not the evidence: minimalism governs what the kernel *contains*, never what the shells may *show*.
